# Планировщик подготовки к сессии

Консольное приложение на Python для итогового проекта курса «Python и основы CS».

## Назначение

Студенты часто теряются в дедлайнах: непонятно, какие задачи самые срочные и в какую неделю возникает перегрузка. Программа загружает задачи по предметам из CSV, позволяет искать их, менять статус и срок, сортировать по дедлайну и формировать отчёт о самых срочных задачах. Состояние сохраняется в JSON, поэтому после перезапуска работа продолжается с того же места.

## Требования и запуск

- Python 3.7 или новее.
- Используется только стандартная библиотека, `requirements.txt` не нужен.

Запуск из корня папки `planner`:

```
python main.py
```

Запуск тестов (тоже из корня папки `planner`):

```
python -m unittest tests.test_models
```

## Команды (пункты меню)

| Команда | Что делает |
|---|---|
| Показать все задачи | Выводит задачи всех предметов |
| Добавить задачу | Запрашивает предмет, название, тип (homework / exam), срок |
| Изменить задачу | Меняет статус (new / in_progress / done) или срок |
| Найти задачу | Поиск по названию |
| Сортировка по дедлайну | Выводит задачи от самого раннего срока к самому позднему |
| Отчёт | Формирует отчёт о срочных задачах и сохраняет его в JSON |
| Импорт из CSV | Загружает задачи из `data/tasks.csv` |
| Выход | Сохраняет состояние и завершает работу |

Названия пунктов в самой программе могут отличаться, ориентируйтесь на меню в `ui.py`.

## Архитектура

Модули:

- `models.py`: предметная область (`Planner`, `Course`, `Task`, `Homework`, `Exam`), проверки данных, собственные исключения, собственные поиск и сортировка.
- `storage.py`: чтение CSV построчно через генератор `read_csv_generator`, запись и чтение JSON.
- `ui.py`: меню, ввод пользователя с проверкой, вывод списков и отчётов.
- `main.py`: связывает модули и настраивает `logging`.

Классы и связи:

- Композиция: `Planner` содержит предметы `Course`, а `Course` содержит задачи `Task`.
- Наследование: `Homework` и `Exam` являются `Task`.
- Полиморфизм: метод `priority()` определён в `Task` и по-своему реализован в `Homework` и `Exam`. Планировщик вызывает его одинаково для любой задачи.
- `@property` защищает данные: название не может быть пустым, дедлайн проверяется на корректность формата и даты, статус принимает только допустимые значения.
- `dataclass` `ReportRow` описывает строку отчёта.

Схема классов: `docs/class_diagram.png`.

## Алгоритмы и структуры данных

| Что | Где | Сложность |
|---|---|---|
| Линейный поиск задачи по названию (свой) | `find_task_by_title` | O(n) |
| Сортировка вставками по дедлайну (своя) | `get_all_tasks_sorted_by_deadline` | O(n²) |
| Доступ к предмету по названию | `dict` в `Planner` | O(1) |
| Хранение задач в порядке добавления | `list` в `Course` | добавление O(1) |

Линейный поиск не требует отсортированных данных. Встроенные `sorted()` и `.sort()` для обязательной сортировки не используются.

## Поток данных

Чтение CSV (генератор) → проверка строки → преобразование в объект `Task` → обработка (поиск, сортировка, отчёт) → запись в JSON.

Генератор отдаёт строки по одной, поэтому весь файл не загружается в память.

## Формат данных

Входной CSV (`data/tasks.csv`):

```
course,title,type,deadline,status
Python,Лабораторная №3,homework,2026-10-25,new
Математика,Итоговый тест,exam,2026-12-15,new
```

Выходной JSON (`data/state.json`):

```json
{
  "courses": [
    {
      "name": "Python",
      "tasks": [
        {
          "title": "Лабораторная №3",
          "type": "homework",
          "deadline": "2026-10-25",
          "status": "new"
        }
      ]
    }
  ],
  "report": {
    "this_week": ["Лабораторная №3"]
  }
}
```

## Обработка ошибок и логирование

- Собственные исключения: `InvalidTaskError` (некорректные данные задачи) и `TaskNotFoundError` (задача не найдена).
- Ошибки ловятся конкретными типами, пустого `except` нет.
- Некорректная строка CSV не пропускается молча: она записывается в журнал с указанием проблемы.
- `logging` пишет в `planner.log`: загрузку файлов, добавление и изменение задач, ошибки.

## Тестирование

Автоматические тесты лежат в `tests/test_models.py`. Таблица тест-кейсов, ручная трассировка сортировки и запись об исправленном дефекте находятся в `docs/test_cases.md`.

## Ограничения

- Даты вводятся только в формате ГГГГ-ММ-ДД.
- Состояние хранится в одном JSON-файле, одновременная работа нескольких пользователей не поддерживается.
- Интерфейс только консольный.
- Сортировка вставками подходит для десятков задач; на очень больших объёмах будет медленной (O(n²)).
- Названия задач внутри одного предмета должны быть уникальными.
